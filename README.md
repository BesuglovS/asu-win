# asu-win — загрузка оценок преподавателя в АСУ РСО

Автоматизация переноса оценок из электронного журнала преподавателя
(**j-web**, `C:\websites\na\j-web`, БД SQLite) в **АСУ РСО** («Сетевой Город.
Образование», https://asurso.ru/), в электронный классный журнал преподавателя
**Безуглова С.В.**

Работает браузерной автоматизацией (Playwright) плюс прямыми запросами к webapi
АСУ РСО с сессионным токеном `at` — по образцу проекта `C:\r` (расписание, ВД,
посещаемость, платные).

## Как это работает (кратко)

1. `jweb.py` читает из БД j-web «класс → предмет → урок(дата) → оценки(ученик,
   значение, тип работы)».
2. `grades_upload.py` логинится в АСУ РСО, открывает **Журнал → Классный журнал**,
   выбирает класс/предмет/период и получает сетку через
   `GET /webapi/grade/journal`.
3. Каждый урок j-web сопоставляется с «датой занятия» (classMeeting) в АСУ РСО по
   дате, каждый ученик — по ФИО, тип работы — с типом задания АСУ РСО.
4. Оценки пишутся методом `POST /webapi/grade/journal/quickedit`.

Подробности, обнаруженные endpoints и подводные камни — в `AGENTS.md`.

## Установка

```bat
pip install -r requirements.txt
python -m playwright install chromium
copy .env.example .env      :: заполнить ASURSO_LOGIN / ASURSO_PASSWORD
```

## Команды

```bat
python grades_upload.py list      :: показать оценки из источника j-web (без браузера)
python grades_upload.py fetch     :: скачать оценки с боевого j-web (HTTP-экспорт)
python grades_upload.py login     :: проверить авто-вход (вход + выход)
python grades_upload.py discover  :: разведка экрана журнала АСУ РСО (снимки/сеть)
python grades_upload.py scan      :: (чтение) предметы класса и содержимое сеток  [PROBE_CLASS=8а]
python grades_upload.py selftest  :: безопасный тест записи (переустановка существующей оценки)
python grades_upload.py plan      :: сопоставить всё и показать план (без записи) → plan.json
python grades_upload.py run       :: залить оценки (по options.json; по умолчанию dry_run)
python grades_upload.py verify    :: сверить оценки на сайте с БД j-web → verify.txt
python grades_upload.py clear     :: убрать оценки в родном предмете перенаправленных
                                  ::   (сейчас «Труд» 9А–9Г → «Информатика»)
python grades_upload.py dedupe    :: убрать устаревшие дубли оценок резервного типа
                                  ::   (type 10 поверх штатной type 3)
python grades_upload.py assign    :: темы уроков (из КТП) + ДЗ (из j-web) в АСУ РСО
```

Порядок: `fetch` → `list` → `plan` (проверить сопоставление) → задать
`dry_run: false` → `run` → `verify`. При `cleanup_duplicates: true` (по
умолчанию) `run` сам запускает `dedupe` после записи; вручную — отдельной
командой `dedupe` (по умолчанию только отчёт, запись при `dry_run: false`).

## Откуда берутся оценки

Источник выбирается `options.jweb_source` (`auto` по умолчанию):
`http` — с боевого j-web по HTTP (`fetch`, сохраняет `jweb_snapshot.json`);
`snapshot` — из сохранённого снимка (оффлайн); `db` — из локального файла БД j-web;
`auto` — HTTP, если задан `JWEB_EXPORT_TOKEN`, иначе снимок, иначе БД.

HTTP-экспорт реализован в проекте j-web (`GET /api/export/grades`, read-only, по
токену `db/export_token.txt`). Один и тот же токен `JWEB_EXPORT_TOKEN` задаётся в
`.env` обоих проектов; j-web кладёт его на сервер при деплое.

## Настройка

`options.json`:

| Ключ | Значение |
|---|---|
| `dry_run` | `true` — только показать план, ничего не писать (по умолчанию) |
| `org` | организация входа (для журнала — основной филиал «Наянов») |
| `jweb_source` | `auto` \| `http` \| `snapshot` \| `db` |
| `jweb_url` | адрес боевого j-web (по умолчанию `https://j.nayanovaacademy.ru`) |
| `snapshot_path` | файл снимка (по умолчанию `jweb_snapshot.json`) |
| `db_path` | путь к БД j-web (для `jweb_source: db`) |
| `assign_themes` / `assign_homework` | что ставить в режиме `assign` (темы / ДЗ) |
| `homework_default` | текст ДЗ, если в j-web его нет (по умолчанию «Повторение изученного материала») |
| `assign_from` / `assign_to` | диапазон дат для `assign` (`YYYY-MM-DD`/`DD.MM`; пусто — весь период) |
| `overwrite_homework` | перезаписывать уже существующие ДЗ (по умолчанию нет) |
| `subject_aliases` | переименование предметов j-web → АСУ РСО (напр. БАС → Информатика) |
| `class_grade_subject` | правило по параллели: напр. `{"7":"Информатика","8":"Информатика","9":"Информатика"}` — все предметы этих классов → «Информатика» |
| `preserve_classes` | классы, где оценки ставит не только наш пользователь (7В, 7Г — и их подгруппы 7В1/7В2/7Г1/7Г2): синхронизация только добавляющая — существующие оценки не перезаписываются, `clear` их не трогает |
| `only_classes` / `only_subjects` | фильтры (подстроки имён) |
| `months` | ограничить месяцами, напр. `["2026_9","2026_10"]` |
| `limit` | обработать первые N предметов |
| `force` | игнорировать `progress.json` |
| `cleanup_duplicates` | после `run` запускать `dedupe` — убирать устаревшие дубли type 10 поверх штатных type 3 (по умолчанию `true`) |
| `work_type_map` | тип работы j-web → название типа задания АСУ РСО |

Прогресс — `progress.json` (ключи «класс\|\|предмет»). Полный журнал — `run.log`.

### Правило «все оценки 7–9 классов → Информатика»

Задаётся в `options.json`:
```json
"class_grade_subject": { "7": "Информатика", "8": "Информатика", "9": "Информатика" }
```
Все предметы указанных параллелей из j-web пишутся в «Информатику» АСУ РСО
(приоритет выше `subject_aliases`). Практически это добавляет к «Информатике»
«Труд (технология)» 9А–9Г (БАС 8Б–8Г и так шли туда через alias).

Перенос старых оценок «Труда» из одноимённого предмета в «Информатику»:
```
python grades_upload.py fetch
python grades_upload.py plan      :: проверить сопоставление и «нет даты»
python grades_upload.py run       :: (dry_run: false) залить в «Информатику»
python grades_upload.py clear     :: (dry_run: false) убрать из «Труда»
python grades_upload.py verify
```
Перед `run` снять ключи `9X||ТРУД(ТЕХНОЛОГИЯ)` из `progress.json` (или `force: true`),
иначе они пропускаются как уже сделанные. Режим `clear` убирает старые оценки из
родного «Труда» (`quickedit` с `assignId` + `mark: null`). Если оценку типа «ДЗ»
нельзя поставить на прошедший урок (задания ещё нет) — `run` использует
`homework_fallback_type` (по умолчанию «Ответ на уроке»).

## Дубли оценок (`dedupe`)

Когда оценку «ДЗ» нельзя записать в задание «Домашнее задание» (например, на
уроке уже есть ДЗ), `run` использует резервный тип `homework_fallback_type`
(по умолчанию «Ответ на уроке», typeId 10). Позже штатная type 3 может
записаться успешно, а старая type 10 остаётся отдельной колонкой — в журнале
появляются две одинаковые оценки в одной клетке (урок × ученик).

`python grades_upload.py dedupe`:

- строит ожидаемые оценки по **всем** классам и предметам j-web (фильтры
  `only_*` к этой проверке не применяются);
- ищет записи type 10, которых нет среди ожидаемых, но которые повторяют
  штатную type 3 тем же значением в той же клетке;
- дополнительно требует, чтобы у задания type 10 не было
  `issueClassMeetingId` (след резервной записи), а класс не входил в
  `preserve_classes`;
- удаляет только такие записи (`quickedit` с `assignId` + `mark: null`),
  оставляя штатную type 3;
- пишет отчёт `grades_discovery/duplicates.json`.

По умолчанию `dedupe` работает в режиме просмотра. Запись — при
`dry_run: false`. При `cleanup_duplicates: true` (по умолчанию) `run` вызывает
`dedupe` автоматически после загрузки; это добавляет полный проход по журналу.
Оценки в `preserve_classes` (7В/7Г) не затрагиваются.

Важно: `dedupe` убирает **лишние колонки-дубли**. Случаи, когда в одной клетке
оказываются разные значения из совмещённых уроков («Информатика» + «Труд»/БАС),
он не исправляет — это отдельный конфликт, видимый в `verify`.

## Безопасность

- `.env` и всё рабочее (чекпоинты, логи, разведка) — в `.gitignore`.
- Логин/пароль хранятся только в `.env`; в чат/логи не выводятся.
- Скрипт всегда делает **Выход** в конце (иначе копятся параллельные сеансы и
  АСУ РСО показывает «Предупреждение о безопасности»).
- По умолчанию `dry_run: true` — реальная запись только по явному включению.
