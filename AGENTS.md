# AGENTS.md — asu-win: загрузка оценок преподавателя в АСУ РСО

Контекст проекта, команды, найденные API и подводные камни. Проект переносит
оценки из журнала **j-web** в **АСУ РСО** (https://asurso.ru/) для преподавателя
**Безуглова С.В.**

## Что это

- **Источник**: проект `C:\websites\na\j-web` — электронный журнал преподавателя
  (PHP + SQLite, `db/app.db`). Таблицы: `classes`, `subjects`, `students`,
  `lessons`, `marks`, `quarters`.
- **Приёмник**: АСУ РСО, экран **Журнал → Классный журнал**
  (`/app/school/journal/`).
- **Способ**: Playwright управляет входом и выбором фильтров, а данные читаются и
  пишутся прямыми запросами к webapi с сессионным токеном `at`. Это надёжнее
  postback'ов, но требует активной сессии браузера (как в проекте `C:\r`).

Рабочая директория — не git-репозиторий. Python 3.13+, playwright ≥ 1.40.

## Команды

```bat
python grades_upload.py list       :: оценки из источника j-web (без браузера)
python grades_upload.py fetch      :: скачать оценки с боевого j-web (HTTP-экспорт)
python grades_upload.py login      :: проверить авто-вход (вход + выход)
python grades_upload.py discover   :: открыть журнал, снять DOM/сеть/скриншоты
python grades_upload.py probe      :: прочитать типы заданий и сетку класса
python grades_upload.py scan       :: (чтение) перебрать предметы класса  (PROBE_CLASS=8а)
python grades_upload.py selftest   :: безопасный тест записи (переустановка оценки)
python grades_upload.py plan       :: сопоставить всё, показать план → plan.json
python grades_upload.py run        :: залить (по options.json; по умолчанию dry_run)
python grades_upload.py verify     :: сверка сайта с j-web → verify.txt
python grades_upload.py clear      :: убрать оценки в РОДНОМ предмете перенаправленных
                                   ::   классовым правилом (сейчас «Труд» 9А–9Г)
python grades_upload.py dedupe     :: убрать устаревшие дубли type 10 поверх type 3
python grades_upload.py assign     :: темы уроков (из КТП) + ДЗ (из j-web) в АСУ РСО
python grades_upload.py final      :: итоговые за период по средней (Журнал → Итоговые
                                   ::   отметки); вверх при дробной части >= 0,6
python grades_upload.py final_cleanup :: убрать итоговые в ЧУЖИХ группах, где
                                   ::   подпись «последнее изменение — Безуглов»
```

`PROBE_CLASS` / `PROBE_SUBJECT` (env) задают класс/предмет для `scan`/`selftest`.

## Модель данных j-web (`jweb.py`)

- Класс: `classes.name` (напр. «9 А»), `norm` → `9А`.
- Предмет привязан к классу: `subjects.class_id`.
- Урок: `lessons(subject_id, class_id, date)`.
- Оценка: `marks(student_id, lesson_id, value 2..5, work_type)`.
  По умолчанию берутся только итоговые попытки (`is_current=1`); переписывания
  (`is_retake=1`) пропускаются.
- Типы работ (`work_type`): `lesson`, `control`, `homework`, `answer`, `ДЗ`, `СР`
  (см. `j-web/src/helpers.php`).
- Ученик: `students.last_name/first_name/middle_name`, `external_id` (= id
  auth-web; для сопоставления с АСУ РСО **не используется** — АСУ РСО имеет свои
  id, матчинг по ФИО).

Модель: `classes[] → subjects[] → lessons[] (date, topic) → marks[] (fio, value,
work_type)`.

## Получение оценок с j-web

Источник выбирается опцией `options.jweb_source` (`auto` по умолчанию):

| Значение | Что делает |
|---|---|
| `http` | `GET {JWEB_URL}/api/export/grades` с заголовком `X-Export-Token: {JWEB_EXPORT_TOKEN}`; сохраняет `jweb_snapshot.json` |
| `snapshot` | читает `jweb_snapshot.json` (оффлайн) |
| `db` | читает локальный файл БД j-web (`JWEB_DB` / `options.db_path`) |
| `auto` | `http`, если задан `JWEB_EXPORT_TOKEN`; иначе `snapshot`, если есть; иначе `db` |

`python grades_upload.py fetch` всегда тянет по HTTP и обновляет снимок. `plan`,
`run`, `verify` и `list` используют `load_model_any` (тот же выбор источника).

HTTP-экспорт реализован в **j-web**: `ExportController@grades` (маршрут
`GET /api/export/grades`, read-only, доступ по токену из `db/export_token.txt`).
Один и тот же токен задаётся в `.env` обоих проектов (`JWEB_EXPORT_TOKEN`);
j-web провизионит его на сервер при деплое (`deploy.ps1`). Формат JSON совпадает
с моделью `jweb.py`, поэтому снимок грузится оффлайн без доступа к БД/сайту.

Фильтры (select): `PCLID_IUP` (класс, значение вида `1515880_0` = `classId_grade`),
`SGID` (предмет; у предмета с подгруппами — отдельные пункты «Предмет/ГрN»),
`TERMID` (период, напр. `332652` = «1 четверть»), `TEACHERNAME` (педагог),
`quick-edit-*`. Сетка появляется по кнопке **«Загрузить»**.

## Сопоставление

1. **Класс**: `jweb.norm_class` (верхний регистр, без `\s.\-`, `И<n>$→<n>`) →
   сверка с текстом пункта `PCLID_IUP` («9 А» и «9а» дают `9А`). **Классы-подгруппы**
   вида «7 А1», «7 А2», «8 А1», «8 А2» — это базовый класс + подгруппа: класс
   матчится по базе (`7А1`→`7А`), а из предметных пунктов предпочитается
   подгруппа «…гр.N» (`_class_base_digit` + `_match_subject_options(group_digit)`).
2. **Предмет**: базовое имя до `/` нормализуется; сверка точная, затем частичная.
   Алиасы — `options.subject_aliases` (напр. «Инженерия беспилотных авиационных
   систем» и «Моделирование и пилотирование беспилотных авиационных систем» →
   «Информатика»). **Подгруппы**
   («Информатика/Инф. гр.1», «…гр.2») обрабатываются автоматически: для каждого
   пункта `SGID` грузится своя сетка, и оценка ученика попадает в ту подгруппу,
   в списке которой он есть (ученик входит ровно в одну подгруппу).
3. **Ученик**: по ФИО — полное совпадение нормы (`Ё→Е`, без регистра/пробелов/точек)
   либо «фамилия + первая буква инициалов» (`jweb.match_fio`).
4. **Урок → дата занятия**: по дате `lessons.date` (YYYY-MM-DD) ищется
   `classMeeting.date`. Если для даты нет занятия в расписании АСУ РСО — оценка
   пропускается (счётчик «нет даты»), т.к. вписать её некуда.
5. **Тип работы → тип задания**: по названию из `options.work_type_map`
   (`lesson`/`answer` → «Ответ на уроке»=10, `control` → «Контрольная работа»=4,
   `homework`/`ДЗ` → «Домашнее задание»=3, `СР` → «Самостоятельная работа»=5).
   Список типов тянется с сайта; id не хардкодятся.
6. **Термин (четверть)**: скрипт перебирает все `TERMID`; оценки раскладываются по
   тем датам, что реально есть в сетке выбранной четверти. Границы четвертей
   знать не нужно.

## Правило по классам (7–9 → «Информатика»)

Опция `options.class_grade_subject` = `{"7": "Информатика", "8": "Информатика",
"9": "Информатика"}`: **все** предметы этих параллелей из j-web пишутся в
указанный предмет АСУ РСО (приоритет выше `subject_aliases`). Номер параллели
берётся из `norm_class` (`8А1` → `8`). Подгруппы (`8А1`/`8А2` → «Информатика/
Инф. гр.1/2») и матчинг учеников работают как раньше.

Практический эффект (по данным j-web 09.10.2026): 8Б–8Г БАС уже шли в
«Информатику» через alias; новое — «Труд (технология)» 9А–9Г (33 оценки)
теперь направляется в «Информатику» (раньше — в свой предмет «Труд»).

**Перенос = заливка + очистка.** Повторный `run` дописывает оценки в
«Информатику», но старые в «Труде» не удаляются. Их убирает режим `clear`
(родной предмет перенаправленных, `dry_run` по умолчанию): по урокам j-web
находит те же клетки `(cmId, studentId, typeId)` в родной сетке и очищает их
через `quickedit` с `assignId` существующего задания и `mark: null` (так же,
как это делает UI) — без `assignId` сервер пытается создать новое «ДЗ» и
отвечает `409 «На выбранный Вами урок уже назначено Домашнее задание»`.

**Конфликт «ДЗ» при заливке.** АСУ РСО не даёт ставить оценку типа «Домашнее
задание» на прошедший урок, если задания этого типа у урока ещё нет
(UI: `canApplyMark`). Поэтому `_build_results` добавляет `assignId`, если
задание нужного типа уже есть (тогда оценка ложится в нужную колонку), а если
задания нет — `run` повторяет запись резервным типом
`options.homework_fallback_type` (по умолчанию «Ответ на уроке»).

**Классы с «чужими» оценками (`preserve_classes`, сейчас 7В и 7Г).** В этих
классах оценки в журнал ставит не только наш пользователь, поэтому
синхронизация для них **только добавляющая**: `run` пишет оценку лишь если в
клетке (урок × ученик) ещё нет оценки ни целевого, ни резервного типа —
существующие не перезаписываются (в логе «сохранены существующие оценки»), а
`clear` эти классы полностью пропускает. Автор оценки через API не виден (в
сетке только `studentId`/`mark`), поэтому любая существующая оценка считается
чужой. `verify` для таких классов показывает «(+N не перезаписано)», а не
«иное». Список задаётся `options.preserve_classes`. Защита базового класса
распространяется и на его подгруппы: `7В` покрывает `7В1`/`7В2`, `7Г` —
`7Г1`/`7Г2` (проверка `_is_preserved` сравнивает и норм. имя класса, и его базу
до цифры подгруппы), поэтому в списке можно указывать только базовые классы.

Порядок переноса:
```
python grades_upload.py fetch     :: свежий снимок j-web
python grades_upload.py plan      :: строки «Труд … → Информатика»; проверить «нет даты»
                                   :: (ключи «9X||ТРУД…» сняты из progress.json,
                                   ::  иначе run их пропустит — либо запуск с force)
python grades_upload.py run       :: dry_run: false — оценки в «Информатику»
python grades_upload.py clear     :: dry_run: false — убрать из «Труда»
python grades_upload.py verify    :: 0 расхождений
```

`assign` (темы/ДЗ) классовым правилом НЕ затрагивается — темы «Труда» ставятся в
свой предмет.

## Режимы и возобновляемость

- `plan` — всегда только чтение; результат в `plan.json`.
- `run` — пишет только при `dry_run: false`. Прогресс — `progress.json`
  (ключ «класс\|\|предмет»), помечается «сделано» только если все группы предмета
  сохранены без ошибок и без несопоставленных учеников. Повторный запуск
  продолжает с неотмеченных; запись идемпотентна (одинаковые значения).
- `dedupe` — отдельный проход по всем классам; при `dry_run: false` удаляет
  устаревшие дубли type 10 поверх type 3. При `cleanup_duplicates: true`
  вызывается автоматически в конце `run` (после закрытия его браузера).
- `limit` применяется после отбрасывания уже сделанных (не зацикливается).
- `only_classes` / `only_subjects` / `months` — фильтры (к `dedupe` не применяются).
- Если упало на одном предмете — остальные продолжаются, ошибка в `progress.errors`.

## Темы уроков и домашние задания (`assign`)

Экран АСУ РСО: **Журнал → Классный журнал → кнопка «Темы уроков и задания»**
(`button.assign-themes-btn`, Angular-роут `/app/school/journal/assignments/`).
Таблица: `Дата | Тема урока | Домашнее задание к текущему уроку | Другие задания | Тип задания`.

Механизм (`python grades_upload.py assign`):

- **Темы**: ставятся через API — `GET /webapi/grade/journal?...` даёт занятия с
  текущим `lessonId`, `GET /webapi/subjectplans/getForSubjectGroup?sgId=` — список
  КТП; на каждое занятие без темы (в диапазоне, в порядке дат) отправляется
  **следующая неиспользованная тема КТП**:
  `POST /webapi/grade/journal/classmeetings/{cmId}/lesson` (body = id урока КТП).
  Темы берутся из КТП АСУ РСО (не из j-web). **Если у предмета нет КТП** — тем нет
  (в интерфейсе тоже нет ссылки «Тема не задана»), такие предметы пропускаются.
- **Домашние задания**: клик по «Добавить домашнее задание» открывает inline-поле
  `input[name=dynText]`; скрипт вписывает текст и жмёт Enter. Текст берётся из
  j-web (`homeworks`: заголовок + описание) для этой даты; если в j-web ДЗ нет —
  подставляется `options.homework_default` («Повторение изученного материала»).
  Существующие ДЗ по умолчанию не перезаписываются (`overwrite_homework`).

API (для сведения): тема — `POST /webapi/grade/journal/classmeetings/{cmId}/lesson`
(body = id урока КТП); ДЗ — `POST /webapi/grade/journal/assignments/home?cmId&issueCmId&homeAssignmentName&classId`.

Опции: `assign_themes`, `assign_homework` (вкл/выкл), `overwrite_homework`,
`homework_default`, `assign_from`/`assign_to` (диапазон дат, `YYYY-MM-DD` или
`DD.MM`; пусто — весь период), `only_classes`/`only_subjects`. Журнал — `run.log`.
По умолчанию `dry_run: true` — только подсчёт пустых тем/ДЗ (без изменений).

`j-web`-экспорт (`/api/export/grades`) теперь отдаёт и **тему урока** (`topic`),
и **домашние задания** (`homework`), и все уроки (не только с оценками).

## Дубли оценок: type 10 поверх type 3 (`dedupe`)

Причина — резервный тип при конфликте «ДЗ». Если `quickedit` не может записать
оценку `work_type=ДЗ` в задание «Домашнее задание» (type 3), `run` повторяет её
типом `homework_fallback_type` (по умолчанию «Ответ на уроке», type 10). Позже
штатная type 3 может записаться успешно, а старая type 10 остаётся отдельной
колонкой: в клетке (урок × ученик) видны две одинаковые оценки.

`python grades_upload.py dedupe`:

- строит ожидаемые оценки по **всем** классам/предметам j-web (фильтры `only_*`
  не применяются — иначе можно ложно признать чужую оценку дублем);
- ищет type 10, которой нет в ожидаемых, но которая совпадает по значению с
  ожидаемой type 3 в той же клетке (`sgId + cmId + studentId`);
- требует `issueClassMeetingId = null` у задания type 10 (след резервной записи)
  и отсутствие класса в `preserve_classes`;
- удаляет только такие записи (`quickedit` с `assignId` + `mark: null`), штатную
  type 3 оставляет;
- пишет `grades_discovery/duplicates.json` (кандидаты, удалённые, пропущенные,
  ошибки).

По умолчанию `dedupe` — просмотр; запись при `dry_run: false`. Опция
`cleanup_duplicates: true` (по умолчанию) заставляет `run` вызывать `dedupe`
автоматически после записи (дополнительный полный проход по журналу).
`preserve_classes` (7В/7Г) не трогаются. `dedupe` **не** исправляет конфликты
«разные значения в одной клетке» при совмещении уроков «Информатика» +
«Труд»/БАС — это отдельный класс расхождений в `verify`.

## Итоговые отметки по средней (`final`)

Экран АСУ РСО: **Журнал → Итоговые отметки** (`/app/school/journal/totals/`):
выбор класса/предмета → клик по «1 четверть» открывает окно
`/app/school/journal/totals/edit/?sgId=&termId=` с колонками
«Ученики | Средняя оценка | Оценка». Скрипт делает то же через API (как и
`quickedit` для текущих оценок).

Механика (`python grades_upload.py final`):

- по классам j-web (уникальные; подгруппы «7А1/7А2» → базовый «7А») выбирает
  класс в `PCLID_IUP` и перебирает все его `SGID` — предметы педагога;
- для предмета проверяет `GET /webapi/subjectgroups/<sgId>`
  (`gradingSys` должен быть `Mark`) и `GET /webapi/grade/journal/totals/edit`
  (`canEditTotals`); **обязательно** сверяет `teachers` с `final_teacher`
  (по умолчанию «Безуглов») — группы других преподавателей пропускаются;
- для каждого уже начавшегося периода (`startDate <= сегодня`) читает средние
  `GET /webapi/grade/journal/average?sgId=&termId=` и текущие итоговые
  `GET /webapi/grade/journal/totals?sgId=&termId=`;
- итоговая = `floor(avg)`; если дробная часть `>= final_round_threshold`
  (0.6) — `floor+1`. Примеры: 4.40→4, 4.59→4, **4.60→5**, 4.75→5, 3.67→4,
  2.75→3, 5.00→5;
- сохраняет только учеников ЭТОЙ группы (`average` текущего `sgId`) через
  `POST /webapi/grade/journal/totals?sgId=&termId=` с телом
  `[{"studentId":…, "mark":…}]` — тот же вызов, что кнопка «Сохранить».
  **Важно:** `GET totals?sgId` возвращает итоговые и второй подгруппы того же
  предмета; если добавить их в payload, сервер отвечает
  `409 «Ошибка обращения к базе данных»`. В статистике `changed` считаются
  только реально изменённые значения;
- `preserve_classes` (7В/7Г): существующие итоговые не перезаписываются,
  заполняются только пустые клетки (как «только добавляющая» логика `run`);
- пустые средние (нет оценок) пропускаются; `NotRated`/`Pass` — без итоговых.

Опции: `dry_run` (по умолчанию true — только отчёт `final_report.json`),
`final_terms` (напр. `["1 четверть"]`; пусто — все начавшиеся периоды),
`final_overwrite` (перезаписывать существующие, по умолчанию true),
`final_round_threshold` (0.6), `final_teacher` (по умолчанию «Безуглов»;
пусто — без фильтра), `only_classes` / `only_subjects`.
Отчёт: `final_report.json` (по каждому классу/предмету/периоду — средние,
рассчитанные оценки, `was`, изменения, ошибки).

### Очистка ошибочных итоговых (`final_cleanup`)

Если итоговые случайно выставлены в группах других преподавателей, их можно
убрать по подписи внизу **классного журнала**:
`Последние изменения внесены 24.10.26 18:22, пользователь Безуглов Сергей
Викторович`. Скрипт открывает **Журнал → Классный журнал**, для каждой группы
из отчёта `grades_discovery/final_other_teachers.json` (только `changed > 0`)
выбирает класс/предмет/период, жмёт «Загрузить» и читает `.alert` с текстом
«Последние изменения…».

- Совпадение: в подписи есть `final_cleanup_user` («Безуглов») и время не
  старше `final_cleanup_hours` (2 ч, отсечка фиксируется на старте прогона).
- **Внимание:** очистка удаляет ВСЕ итоговые выбранного периода в группе, а не
  только наши изменения; исходные значения перед очисткой не сохраняются.
  Поэтому запускать только после резервной копии БД АСУ РСО.
- Очистка: `GET totals` → `POST /webapi/grade/journal/totals?sgId&termId` с
  `[{"studentId":…, "mark": null}]` для всех учеников периода
  (`final_cleanup_term`, по умолчанию «1 четверть»), затем контрольный `GET`
  (должно остаться 0 оценок).
- Группы, где после нас уже что-то изменил другой преподаватель, пропускаются.
- Свои группы (`subjectgroups.teachers` содержит `final_teacher`) не трогаются.
- По умолчанию `dry_run: true` — только отчёт `final_cleanup.json`.

Опции: `final_cleanup_user`, `final_cleanup_hours`, `final_cleanup_term`,
`final_cleanup_report`, `final_teacher`, `dry_run`.

## Подводные камни

- **ID АСУ РСО пересоздаются** между экспортами/годами: `classId`, `sgId`, `cmId`,
  `typeId` не хардкодить — только получать в рантайме (скрипт так и делает).
- **Сессия не переживает закрытие браузера** — каждый запуск логинится заново
  через `.env`; в конце обязателен **Выход** (иначе копятся параллельные входы и
  всплывает «Предупреждение о безопасности», блокирующее клики).
- **Прямой deep-link** на экран журнала может сбросить сессию — открывать только
  через меню «Журнал → Классный журнал».
- **Вход строго в основной филиал «Наянов»** (не «УСОПДОД»/«(ДО)»).
- **Подгруппы**: у предмета несколько `SGID`-пунктов; нельзя сваливать всех
  учеников в одну группу — матчинг по вхождению ученика в список группы.
- **`quickedit` валидируется по «последней открытой» группе (`last-access`).**
  Если у предмета 2+ подгруппы, скрипт сначала собирает результаты по всем
  группам, и к моменту записи активной в интерфейсе остаётся ПОСЛЕДНЯЯ. Тогда
  POST для первой подгруппы получает `409 {"message":"нет доступа"}` — при
  верном `sgId` в теле. Лечится перевыбором `SGID` этой подгруппы и
  принудительной перезагрузкой сетки (`_load_grid` → `GET /webapi/grade/journal`,
  обновляет `last-access`) непосредственно перед `api_post` (см. `cmd_plan_or_run`,
  блок «перед записью»). Классы без подгрупп (один `SGID`) не затронуты.
- **`GET /webapi/grade/journal/totals?sgId` возвращает итоговые ВСЕХ подгрупп
  предмета.** Для `final` в `POST totals` отправляются только ученики текущей
  группы (`average` этого `sgId`). Лишние ученики второй подгруппы дают
  `409 «Невозможно сохранить оценки / Ошибка обращения к базе данных»`; это
  исправлено (payload строится только по `avg`). Если сервер всё же ответил
  409, `final` переходит на экран `totals/edit/` и повторяет POST оттуда.
- **Предмета БАС в АСУ РСО у 8 А нет.** `scan` класса 8а: 16 предметов; из
  «информатических» — только «Информатика/Инф. гр.1» (`sgId 8139172`) и
  «Информатика/Инф. гр.2» (`sgId 8529790`). Поэтому оценки j-web
  «Моделирование и пилотирование БАС» (и «Инженерия БАС» 7 Б) обязаны
  раскладываться в эти подгруппы по вхождению ученика, а не писаться в отдельный
  предмет БАС.
- **Дубли оценок**: быстрый режим переустанавливает оценку клетки
  (cm, ученик, тип) — повторный запуск не создаёт дублей для того же типа.
  Но разные типы работы дают разные столбцы-оценки в клетке (как в АСУ РСО).
  Отдельный случай — резервная type 10, оставшаяся после конфликта «ДЗ»:
  `run` теперь при `cleanup_duplicates: true` запускает `dedupe` и убирает такие
  записи, если они не нужны ни одному предмету j-web и дублируют штатную type 3.
  «Разные значения в одной клетке» при совмещении уроков `dedupe` не трогает.
- **Плашка «Сохранить пароль?» не появляется**: при запуске Chromium менеджер
  паролей отключён — флаги `--disable-save-password-bubble` +
  `--disable-features=PasswordManagerOnboarding,PasswordLeakDetection,…` и
  предзасеянный профиль `Default/Preferences` (`password_manager_enabled=false`).
  Системную плашку браузера Playwright кликнуть не может, поэтому её глушат на
  уровне запуска (см. `asurso_common.launch`).
- **Список `SGID` на экране журнала содержит ВСЕ предметы класса, а не только
  предметы текущего педагога.** Для `final` это критично: без фильтра по
  `subjectgroups/<sgId>.teachers` скрипт выставит итоговые чужим преподавателям.
  Всегда проверяйте `final_teacher` (по умолчанию «Безуглов»).
- **`work_type_map`**: если в школе принято складывать базовые оценки в
  авто-задание «Домашнее задание», поменяйте `lesson` → «Домашнее задание».
- **`work_type` в проде j-web — свободный текст**, а не коды: например «Урок»,
  «ДЗ», «Сам/р», «Python темы 1-8 квизы + контекст урока 8». Тип задания АСУ РСО
  определяется: точное имя → частичное → эвристика по ключевым словам
  (`_resolve_type`: ДЗ/домаш → Домашнее задание, сам/СР → Самостоятельная,
  контр/КР/диктант → Контрольная, квиз/тест → Тестирование, урок/ответ → Ответ на
  уроке…). Нераспознанные значения (напр. «Телефон») пропускаются — смотреть
  предупреждения `нет типа задания` и при необходимости задать явную пару в
  `work_type_map` (ключ — сам текст work_type).
- **Даты уроков j-web и расписания АСУ РСО могут расходиться на 1–2 дня**.
  Опция `date_tolerance_days` (по умолчанию 0 — строго по дате) разрешает
  сопоставление с ближайшим занятием в пределах допуска; переносы печатаются
  (`j-web→сайт±дн`). Дат-кандидатов рядом нет — перенос однозначен.
- У предмета бывает **2 занятия в день** (разные слоты). Если несколько
  `classMeeting` на одну дату, берётся первое (меньший слот); оценки разных типов
  работы в одну клетку не конфликтуют (разные задания).
- **j-web prod-БД**: локальная `j-web/db/app.db` — пустая dev-БД. Реальные данные
  на сервере; путь задаётся `JWEB_DB` или `options.db_path` (можно скопировать
  боевую `app.db` локально и указать на неё).
- **PowerShell 5.1** портит кириллицу при записи файлов через `Set-Content`/`>`:
  JSON/логи писать только Python'ом (скрипт так и делает).

## Дальнейшие шаги

1. Задеплоить j-web (`.\deploy.ps1`) — это создаст на сервере `db/export_token.txt`.
   Проверить: `python grades_upload.py fetch` (тянет оценки по HTTP → `jweb_snapshot.json`).
2. `python grades_upload.py list` — убедиться, что данные получены.
3. `python grades_upload.py plan`, проверить `plan.json` (сопоставление классов,
   предметов, «нет даты», несопоставленных учеников).
4. Включить `"dry_run": false`, запустить `run` (при желании пакетами: `limit`).
   При `cleanup_duplicates: true` он сам запустит `dedupe` после записи.
5. `python grades_upload.py verify` — расхождений быть не должно.
6. Если `run` выполнялся с `cleanup_duplicates: false` — отдельно
   `python grades_upload.py dedupe` (сначала просмотр, затем запись).
7. При необходимости уточнить `work_type_map` и `SUBJECT_ALIASES`.
